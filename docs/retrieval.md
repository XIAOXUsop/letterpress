# 面向 agent 的检索

`npm run wiki:ask -- "中文正文的理想行宽是多少"`

它把一个自然语言问题，编译成一份**带元数据的 context pack**，
而不是把整站塞给模型。代码在 `src/lib/wiki/retrieve.ts`，
金标在 `knowledge/questions.md`。

## 材料之间的关系

材料包的 `relation` 与发布链接图使用同一套解析：支持 slug、唯一标题、
大小写与空白归一化、显示别名和小节链接。围栏及行内代码中的链接示例不建立
关系，同名标题也不会任选一页。明确 slug 可以消除歧义。

输出区分主命中、声明关系、正文引用和无直接关系，并保留引用方向。
直接链接只证明两篇内容存在引用，不证明它们的结论相互支持，也不推断多跳关系。

## 它和站内搜索是两件事

|  | 站内搜索 | 这里的检索 |
|---|---|---|
| 跑在哪 | 浏览器（Pagefind） | Node（本项目自己的分词器） |
| 给谁用 | 访问者 | agent / 维护脚本 |
| 分词 | Pagefind 按 `<html lang>` 选 | 中文二元组 + 西文词 |
| 可回归吗 | **不能** | 能——金标 23 条 |

**为什么不复用站内搜索**：`scripts/check-search.mjs` 里记着一次实测——
在 Node 里加载 Pagefind 跑查询，得到的结果和真实页面**不一样**
（没有 `document`，`lang` 缺省，「中文排版」从 6 条掉到 1 条）。
任何在 Node 里假装复现浏览器搜索的检查，都会给出错误的结论。
所以这里不假装：它是另一条路径，分词器由我们自己定，因此可复现。

## 为什么不用向量

这个项目的立身之本是「完全离线、可复现、无 Key」。引入 embedding
会一次性摧毁这三样：不同时间跑出不同结果、需要网络与凭据、
而且失败时是**静默的**（召回掉了但没有任何东西会红）。

词法检索在 11 页（wiki + posts）的规模上够用，而且它的失败是**看得见的**。
代价是一条已知的软肋，见文末。

## 两道闸：什么时候该说「不知道」

一个**永远给得出答案**的检索系统，比一个会漏的更危险——
它把「知识库里没有」伪装成「知识库里说有」。
所以 `assess()` 有两道闸，**缺一不可**：

### 闸二：最重的那个实词，知识层得听说过

查询里权重最高的**实词**必须在整个知识层里出现过至少一次。

这条闸是被一个真 bug 逼出来的。实测（2026-09-23）：

```
问：Webmention 是怎么实现的？
→ 候选段落命中了 怎么、么实、实现
→ 覆盖度 0.53，轻松过闸
→ 而全站根本没有 webmention 这个词
```

**检索器用问题的虚词回答了问题的实词。** 根因有两层：
`idf` 把「从未出现」当成了「出现在所有文档里」；
而中文二元组会把词与词的**接缝**也切出来（`怎么实现` → `么实`），
接缝词在语料里真的存在，于是产生了虚假命中。

判据是「**语料里有没有**」，不是「**返回的那几段里有没有**」。
这个区别也是实测定下来的：问「为什么不用 Tailwind」，
`tailwind` 明明在 letterpress 页里，但那一页进包的段落是别的节，
查返回集合会把一个**答得出来**的问题判成「没依据」。

### 闸一：覆盖度，而且按文档算

查询里有多少比例的词真的出现在候选里。**按文档合并，不按段落取最大。**

这一条同样是实测逼出来的：答案横跨同一页的两个小节时，
逐段算的话两段各自都答不全，双双掉到门槛下——
而「这一页答得出来」是**文档级的事实**。段是切法的产物，页才是知识单位。

### 四种词的待遇（`termWeight`）

| 词 | 权重 | 理由 |
|---|---|---|
| 语料里有 | 它自己的 idf | —— |
| 西文 token，语料里没有 | 最稀有词的权重 | 缺席证据。ASCII token 不可能被分词器凭空造出来，判据精度高 |
| 中文实词，语料里没有 | 中位权重的一倍 | 也是缺席证据，但弱得多 |
| 中文接缝词 | **0，不进分母** | 它不是问题的一部分，是分词器的副产物 |

接缝词有两种，两条互补的判据：

- **含虚词的**（`么实`、`站不`）——查一张手工维护的虚词表。
- **跨词接缝的**（`式方` 来自 `样式`+`方案`）——`junctionsOf()`：
  **两个字各自都出现在别的、语料里存在的二元组中**，它就没有自己的字符。
  这条**不需要词典**，只读查询自身的结构与语料词表。

## 排序和交付

评分优先考虑实词覆盖，再考虑完整词权重。普通问题中，参考或文献列表不会优先于
正文解释；查询明确询问参考资料时仍可返回这些章节。主命中文档的章节与它显式
引用的邻居先进入候选，再补充其他命中；关系只表示引用，不代表结论相互证明。

默认最多六个章节，每篇最多两个；选中的章节完整返回，保留代码、否定、例外和
更正。`--all` 将章节上限提高到二十。没有硬 token 预算，长章节可能较大，消费方
需要根据模型上下文大小分批处理，不能再次盲截并保留原覆盖度声明。

A/B 等斜杠术语整体保留；中文包名增加复合词身份，普通“语言”不能替代“语言包”。
其余中文主要仍是二元组，这是词法候选检索，不是语义正确性的证明。

## 评测与负向验证

23 条真实金标全部参与判定，没有已知失败的排除项。生产 CLI、召回检查及证据检查
共用发布语料、默认选项和上下文构造；金标解析共用实现，LF 与 CRLF 一致。
回归还实际启动 CLI，证明草稿独有答案不会被验收成有依据，段尾证据不会消失。

`verify:retrieval-gates` 逐一破坏覆盖度、实词识别、接缝识别、单字母权重及问句壳
剔除规则。每次必须由真实金标或独立语义契约捕获；恢复后两者必须通过。
不宣称五条规则各有独有的真实金标，因为语料和排序变化会使规则互相遮蔽。

## 复核输入迁移

来源 ID、版本、定位与原创依据现在参与复核摘要。现有六页仅在旧摘要与原输入
完全一致时迁移公式，并保持正文、来源、review.status 和 checkedAt 不变。
这不是新增人工复核，也不刷新日期。迁移后变更来源或正文会触发过期。

## 验收边界

当前回归集通过不能证明任意未知问题都能得到正确材料。词法相似、引用关系和
复核元数据分别提供不同信息，调用方应阅读完整正文及来源，再形成结论。
检索在离线本地运行，不联网生成答案，也不替人工确认新的 reviewed 状态。
