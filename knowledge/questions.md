# 评测问题集

这份文件是**检索的尺子**。`npm run verify:questions` 会拿它跑
`src/lib/wiki/retrieve.ts`，对不上就红。

## 它为什么必须存在

「检索能用吗」这个问题，**不写下来就没法回答**。没有它，
每次改分词、改权重、改阈值，能得到的结论只有「我试了几个查询，看着还行」——
而那正是本项目反复踩的那类坑：**看起来没问题**。

它同时钉住了一件更微妙的事：**「没有依据」是一个结论，不是失败。**
一个永远给得出答案的检索器比一个会漏的更危险——它把「知识库里没有」
伪装成「知识库里说有」。所以下面有一整类问题，**期望的答案就是「没有」**。

## 怎么写一条

```
### 问题的原话（就照你会问的样子写）

期望命中：slug-a、slug-b      # 这些页面**必须**出现在 context pack 里
不得出现：slug-c              # 这些**必须不**出现（可留空）
期望判定：无依据               # 只有「无答案」类才写，表示必须报没有依据
```

- **期望命中列的是页面，不是段落。** 段落切法会随排版调整而变，
  页面不会——把金标钉在段落 ID 上，改一次小标题就要重写一遍金标，
  然后所有人学会不再看它。
- **不得出现**用来抓「捞回一大片」的检索器。只查召回的话，
  一个「每次都返回全部页面」的实现能拿满分。
- **问题用自然语言写，不要凑关键词。** 拿正文里的词去拼查询，
  测的就只是字符串匹配。下面这些问句是**先写问题、再去看命中对不对**的。

## 这份金标的已知局限（写在前面，免得被它的绿灯误导）

1. **它是我写的，而语料也是我写的。** 我知道答案在哪一页——
   真实用户不知道。所以它对「召回」的检验比看上去弱。
   它真正能挡住的是**回归**：改了检索器之后原来对的变错了。
2. **「无答案」这一类覆盖的是英文专名与英文缩写**（`Stripe`、`Webmention`、`i18n`）。
   中文提问一个语料里真的没有的主题，**可能仍然给出「有依据」**——
   原因与实测写在 `src/lib/wiki/retrieve.ts` 里 `termWeight` 的注释里。
   要真正解决需要词典或向量，而向量会摧毁本项目「离线、可复现、无 Key」
   的立身之本。这条限制不修，但要说出来。
3. **它不评价答案对不对。** 检索器只负责选材料，不负责下结论——
   后者是模型的事，只能人读。
4. **闸一（覆盖度门槛）当前没有被任何一条金标量到。** 实测：
   把 `MIN_COVERAGE` 改成 0，下面 20 条**一条都不变红**——
   实词闸（闸二）先一步拦住了那些查询。
   闸一只在 `src/lib/wiki/retrieve.test.ts` 里被单独量。
   **这条写在这里，是因为「一个没被量过的闸」和「没有这个闸」是一回事**，
   而金标全绿会让人以为两道闸都被验过了。
   要补一条金标来量它，得先找到「所有实词都在语料里、却没有一页答得出来」
   的自然问句——在 6 页的语料上没找到，硬造一个就是凑用例。

## 跨文档组合

是因为 context pack 的全部意义就是「组合」——一次只捞一页的实现，
在单页问题上照样满分。

## 冲突

同一页里既有结论、又有对它的**撤回或更正**。
这一类要的不是「找到答案」，而是「**答案和它的更正一起被找到**」——
只捞到前者比什么都没捞到更糟。

### 66ch 排中文会排成多少字一行？

期望命中：cjk-typography
不得出现：
说明：正文里原先写「约 130 字」，页内勘误指出该算式方向反了，
应当是约 33 字。**两段都必须进包**——只给正文会复述一个已被推翻的数字。

### 一个来源改动会影响多少个页面？

期望命中：llm-wiki
不得出现：
说明：正文引用了「10 到 15 个页面」这个数，紧随其后的引用块说明
**它确实有出处**（Karpathy gist 的 Ingest 段落原文），
但**是作者描述个人工作流时的经验性例子，不可泛化、不应作 KPI**。
和上一条同构：**结论与对结论的分寸必须一起给。**
（这条问句此前写的是「它没有出处」——那是错的，金标会去检索一句页面上
不存在的话，于是它量的是一个不存在的东西。**金标自己也会过期。**）

## 过期

答案曾经是对的，**现在不对了**，而页面自己还没改。
这一类**不是检索器能修的**——检索器只能把页面原样递过来。
它在这里的作用是**把问题暴露出来**：只要金标是绿的，
说明检索器确实把那一页捞上来了，那么页面上的陈旧内容就有机会被读到。

### 来源登记与版本固定实现了吗？

期望命中：llm-wiki
不得出现：
说明：这一页有一张「已实现 / 计划实现」表。
**2026-09-23 实测：表里三行写着「计划中，尚未实现」，而它们全都已经落地**
（`knowledge/sources/*.json`、`Doc.sources` / `Doc.review`、
`scripts/wiki-impact.mjs`）。lint 只管断链与孤儿页，发现不了这件事。
`verify:` 声明就是为这类陈旧而加的——见 `src/lib/wiki/verify.ts`。

## 无答案

知识层里**没有**这个内容。期望的判定是「没有依据」。

这一类的价值全在于：**一个永远给得出答案的检索器，只会在这一类上失败。**

### 这个主题支持哪些语言包？

期望命中：
不得出现：
期望判定：无依据
已知局限：语料里**有**「语言」和「支持」两个词（「语言标签不对」「尚不支持」），
所以两道闸都放行——覆盖度 45%。词法检索**分不出**「语言」和「语言包」是不是一回事。

说明：这一条由**闸一**（覆盖度）拦下，而不是闸二——
`语言` 在语料里出现过（「语言标签不对」），所以实词闸放行。
**两道闸各挡一类，这条是闸一那一类的代表。**

### 怎么加评论区？

期望命中：
不得出现：
期望判定：无依据
说明：中文提问、无西文专名、覆盖度贴着门槛。
**这一条是最脆的**：它离门槛只有几个百分点。

红的是这条金标，而不是某个用户某天发现检索开始胡说。
