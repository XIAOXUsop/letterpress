一份由 AI 持续读写的结构化知识库，通常就是一堆 markdown 文件。

与 RAG 的关键区别：RAG 里新文档只会被索引，**永不改变、永不连接**；
LLM 知识库里新素材进来会触发一次**编译**——更新既有页面、建新页、加链接、
标记矛盾。有人的说法是「摄取是一次重构，不是一次追加」，
一份来源可能改动 10 到 15 个页面。

## 三层结构

| 层 | 作用 | 本项目里对应 |
|---|---|---|
| 原始素材 | 不可变的输入 | `src/content/posts/` |
| 知识层 | agent 维护的结构化页面 | `src/content/wiki/` |
| schema | 告诉 agent 怎么维护 | `AGENTS.md` |

## 三个操作

- **摄取（Ingest）**：读入来源，写摘要页，更新索引与相关条目页
- **查询（Query）**：从相关页面综合出答案，并给出处
- **体检（Lint）**：检查矛盾、过时、孤儿页、断链

## 本项目的取舍：把 lint 做成确定性的

Karpathy 那套的体检是「让 agent 定期看看」。这**不是工程方案**——
它不可复现、不可回归、进不了 CI。

所以本项目只把**机械可判定的那部分**做成代码（`src/lib/wiki/lint.ts`）：

- 断链、重复 slug → 错误级，构建失败
- 孤儿页、缺摘要、空正文 → 警告级
- 摘要过长 → 提示级

**语义级的检查仍然留给 agent**（「这两页说法矛盾」「这条结论已被推翻」），
但地基是机械的。没有地基的话，agent 每次检查的结论都不一样，
你没法判断「这次多了三条告警」是内容变了还是模型心情变了。

## 与「数字花园」的关系

数字花园（digital garden）强调**公开的、持续演化的笔记**，
不按时间排列，靠链接组织。LLM 知识库是它的一个变体：
区别在于**维护者从人换成了 agent**。

两者面对同一个问题：**怎么防止腐烂**。花园派的做法是「定期打理」，
LLM 知识库派的做法是「让 agent 定期重构」。本项目认为两者都不够，
**机械检查必须先进 CI**。

## 为什么博客适合这个模式

博客天生是**流**——按时间排，读过就沉底。
但知识是**网**：你写过三篇关于排版的文章，它们之间的共性不会自动浮现。

加一层知识库，文章仍然是流（读者的入口），但知识层把散落各篇的东西
连起来。读者（和人以外的读者）不必读完所有文章才能拼出全貌。
